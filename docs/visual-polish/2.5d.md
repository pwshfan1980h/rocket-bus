# Could Rocket Bus be 2.5D?

Short answer: yes. The cheap and safe way keeps every bit of gameplay in 2D and
only renders the road in 3D. The mock-up shows what that looks like:
`mock25d.png` (1-1) and `mock25d_volcano.png` (5-1). It is level 1-1's real
terrain extruded into 3D, the real bus sprites as flat cards, a camera tilted
14°, and a 480x270 render scaled up with nearest filtering. The existing 2D
parallax sky sits behind it. The script is `mock25d.gd.txt`. It's throwaway: it
reads the game but changes nothing.

## How the game is built today
- **Physics:** Godot 2D rigid bodies, with wheels on spring joints. Terrain
  collision is convex strips built from the road polyline in `terrain.gd`. Bot
  tuning, landing grades and flips all depend on this.
- **Terrain look:** `Polygon2D` bodies with `terrain.gdshader`, a road-band mesh,
  and overlay draws for ramps, cliffs, mud and ice.
- **Bus:** about 20 layered 100x53 sprites on the chassis, plus `PointLight2D`
  lights, `CPUParticles2D`, ragdolls and debris.
- **World:** the backdrop is screen-space 2D. Props, life, weather and foreground
  are all `_draw()` code in world space.
- **Renderer:** Compatibility (GL ES 3 / WebGL 2), shipped to the web.

## Options

### A. "Fake depth" in 2D (no 3D at all)
Add more parallax rows, a thin road top face drawn as a strip above the road
line, props on two depth rows (some scaled down, darker and behind the road;
some in front), and the bus's far-side wheels drawn darker and offset.
- **Physics, bot, gameplay:** untouched.
- **Art:** new draw code only. The pixel look and web build are unaffected.
- **Effort:** 2–4 days. **Risk:** low.
- **Payoff:** modest. It reads as "richer 2D", not 2.5D.

### B. Hybrid: 3D render, 2D gameplay (recommended, shown in the mock-up)
Keep the 2D physics world exactly as it is, as an invisible simulation. Mirror
its state into a 3D scene each frame:
- **Road:** the terrain polyline extruded into a road slab (top face plus front
  face with strata), built once per level. The mock-up does this in about 60
  lines.
- **Bus:** a stack of `Sprite3D` cards that copies the chassis position and
  rotation (x, y, angle), plus a darker far wheel pair. It stays crisp pixel art
  because it's still the same sprites.
- **Props:** billboards or simple low-poly meshes placed on both sides of the road
  (z), so the road runs *through* the scenery.
- **Camera:** a perspective `Camera3D` with a 10–15° tilt that follows the bus.
  It renders into a 480x270 `SubViewport` scaled up with nearest filtering, so
  pixels stay crisp. The 2D backdrop and HUD stay as they are, behind and on top.
- **Particles, lights, text:** these stay in 2D overlay layers mapped through the
  3D camera. Alternatively, port the few important ones (rocket flame, dust,
  lava glow) to 3D.

What this means for each part:
- **Physics:** unchanged. The bot, grades and levels all keep working.
- **Terrain:** a new mesh builder. The current shaders port almost directly
  (they're already functions of x and depth).
- **Bus:** a thin 3D puppet. Ragdolls and debris need puppets too, or can stay as
  a 2D overlay.
- **Art:** existing sprites are reused. Props (about 25 kinds in `props.gd` and
  `life.gd`) need billboard versions, rendered from the current draw code into
  textures once.
- **Web:** 3D in Compatibility on WebGL 2 is fine at this scale: a few thousand
  triangles, unshaded materials, a 480x270 target. Lights are cheaper as unshaded
  plus baked glow than as real 3D lights.

**Effort:** about 2–3 weeks for full parity across 7 worlds and the story mode.
It splits into phases: road and camera, bus puppet, props, effects, then night
lighting and polish. The phases can ship one at a time behind a setting, since
the 2D renderer stays as a fallback.

**Risk:** medium. The main risks are:
- keeping 2D overlay effects lined up with the 3D camera
- far-side wheel and ragdoll puppets
- the time spent porting about 1,500 lines of `_draw()` scenery

### C. Full 3D
3D physics (`RigidBody3D` or `VehicleBody3D` locked to a plane), 3D or voxel
assets and a 3D camera.
- **Physics:** rewritten. All the tuning, the bot, landing grades and flips need
  re-tuning.
- **Art:** new 3D models for the bus, passengers, props and every world. The
  pixel-art identity is mostly lost, unless you go voxel or low-res 3D.
- **Web:** heavier, so check performance on low-end devices.
- **Effort:** 2–3 months. **Risk:** high, because it's effectively a new game
  with the same rules.

## Recommendation
**B, done in phases.** It gives the "road through a world" depth you see in the
mock-up, keeps every gameplay system and the pixel look, and can be tried behind
a toggle. Start with phase 1, the road slab, camera and bus puppet in one world,
and play it before committing to the rest. If the tilt or camera feels wrong in
motion, option A's tricks are a cheap fallback.

## Open choices for the user
- **Camera tilt:** subtle (8–10°), or the mock-up's 14°, which is a stronger
  diorama feel.
- **Props:** billboards that keep the pixel look, or chunky low-poly meshes.
- **2D renderer:** keep it as a setting, or replace it.
